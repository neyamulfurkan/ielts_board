What is the Schema? Every day, Claude MUST end its response with a strict [SESSION_DATA]...[/SESSION_DATA] block. This website parses that block to automatically update your tracker. The schema below defines every field — its format, meaning, and example. Claude's prompt includes these rules, so it knows exactly what to produce.
Session Data Schema
🔒 Block Format (required exactly)
Claude must always end its response with this exact structure:

[SESSION_DATA]
field_name: value
field_name: value
...
[/SESSION_DATA]

Rules:
• Each field on its own line. Format: key: value
• No blank lines inside the block
• Multiple values separated by | (pipe with spaces)
• No markdown, no bold, no asterisks inside the block
• All fields must be present every session, even if value is none

❌ Common Mistakes Claude Must NOT Make
• Do not use markdown inside the block (no **bold**, no # headers)
• Do not use newlines inside a single field value
• Do not skip any field — all 18 fields must appear every session
• Do not add extra text after [/SESSION_DATA]
• Do not use commas to separate multi-values — use | (pipe)
• Do not put the block anywhere except at the very end of the response
• Do not write score: 78/100 — just write score: 78
